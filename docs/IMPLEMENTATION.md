# 实施与验收计划

状态：本文为原实施计划；首版已实现并完成测试，实际结果及待真实模型验证项见 [验证记录](./VERIFICATION.md)。目标是首轮开发交付完整核心闭环，“80%”不是保证一个未经验证的工期或完成比例。

## 阶段0：高风险能力验证

- 用户在配置界面填写模型凭证；不在PRD、GitHub或聊天中收集明文Key。
- 真实验证图片理解、结构化草稿、语音转写三个能力。
- 验证08—24点七列布局、任意起始日期、半小时吸附、跨周拖动及滚动防误触。
- 验证Windows本地启动、数据目录、凭证存储与SQLite驱动。

通过标准：使用未预填答案的新图片和新录音，得到真实结果；日历原型能完成跨日期拖动。失败时调整适配器或交互设计后再锁定依赖。

## 阶段1：可靠的本地业务底座

实现数据库迁移、任务／固定事件／安排／跟进／草稿模型，业务命令、版本检查、撤销、备份恢复及本地持久化。

测试关键规则：区间相邻不冲突、重叠被拒绝、重复课程有限学期、单次停课、09:15保留、日期精度、重启恢复、撤销不覆盖新修改。

## 阶段2：完整手工日历

从空白创建项目和任务→拖动排期→部分完成→到期确认→退回清单→跨周重排。增加筛选、历史查看、左右面板收起和独立任务。

固定课程不进入待确认；不会把任务自动顺延到明天。

## 阶段3：网页内AI闭环

图片／文字→提取→澄清→可编辑草稿→采用→本地事务写入→整批撤销。支持一次多条、重复识别、冲突反馈、用户编辑优先和失败重试。

验收必须从空数据库开始，不借助Codex替网页识别或写入任务。关闭Codex后仍可通过网页实际调用配置的模型。

## 阶段4：口述与暂缓跟进

录音→转写→用户编辑发送。暂缓任务保存缺失信息和明确跟进时间；页面运行时显示到期卡片，关闭不提醒，重开补查。跟进卡片不依赖模型接口在线。

## 阶段5：整体交付

桌面快捷方式、服务退出入口、安装说明、模型配置说明、备份恢复说明。SQL和英语显示待开放。空态、失败状态和未保存状态清楚可见。

## 必须通过的端到端场景

| 场景 | 成功标准 |
|---|---|
| 新课表图片 | 修改一条识别值，补学期范围后采用；对应课程正确重复 |
| 模糊作业通知 | 先追问；暂时答不了可保存待补充，不虚构截止日期 |
| 延后讨论 | 采用明确跟进时间，到期显示原任务信息，可继续或延后 |
| 精确面试时间 | 09:15保持原值，错误取整视为失败 |
| 批量草稿 | 取消无关条目；采用只保存所选且不重复 |
| 旧草稿冲突 | 草稿生成后另改日历，采用时检测新冲突，不覆盖 |
| 未完成任务 | 到期待确认，退回清单，用户手动跨周安排 |
| 语音失败 | 权限拒绝、转写失败可恢复，无意外发送或任务写入 |
| 重启 | 图片引用、草稿、对话、任务、跟进仍在 |
| 模型离线 | 手工日历、到期状态和跟进卡片继续工作 |
| 备份恢复 | 在测试数据副本完成恢复比对，密钥不在备份内 |
| Git提交检查 | 无密钥、真实附件、录音、日程库或用户日志 |

普通逻辑和集成测试无需调用付费模型；模型真实验收使用明确配置和受控次数，模拟测试不能取代该验收。
