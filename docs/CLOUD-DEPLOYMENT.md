# 云端部署

代码已支持独立云端服务；本机运行不代表云端已经上线。

## 运行条件

- 一台支持 Node 24+ 或 Docker 的云端服务，单实例运行。
- HTTPS 域名及 TLS 反向代理；代理保持原始 Host。不要将 HTTP 容器端口直接暴露公网。
- 持久磁盘挂载 `/var/data`，运行用户必须可写。SQLite、图片及学习记录均在此路径。
- 服务器时区 `Asia/Shanghai`。滚动多副本部署不适用于当前 SQLite 架构。

## 环境变量

| 名称 | 值 |
|---|---|
| PLANNER_CLOUD | 1 |
| PLANNER_PUBLIC_ORIGIN | 实际 HTTPS 地址，无末尾斜线 |
| PLANNER_LOGIN_PASSWORD | 至少16位随机密码，手机与电脑共用 |
| PLANNER_MASTER_KEY | 32字节随机值的64位十六进制字符串，保存在平台 Secret 中 |
| PLANNER_DATA_DIR | /var/data |
| TZ | Asia/Shanghai |

随机密钥可在可信终端用 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` 生成。不得提交密码和密钥到 Git。加密密钥应安全备份，丢失后需重新配置模型凭证。更换登录密码会使旧登录失效。

## 部署与迁移

1. 托管平台从私有 GitHub 仓库使用 Dockerfile 构建，挂载持久磁盘，配置环境变量及健康检查 `/api/health`。
2. 用实际 HTTPS 地址登录，检查空工作台可保存任务。
3. 本机设置导出完整备份，在云端设置导入。先保留本机原始数据。导入将替换目标工作台内容，勿重复覆盖已有云端修改。
4. 在云端设置重新填写模型 API Key。Windows 加密凭证不能直接迁移；备份不包含凭证。
5. 手机移动网络、电脑 Wi-Fi 分别登录同一网址，验证创建、切回同步、冲突、图片、学习进度和重启后持久保存。
6. 切换完成后，两端均使用云端网址，避免继续往本机副本写入。

Render 支持此 Docker 服务及付费持久磁盘：https://render.com/docs/disks 。免费临时文件系统不能用于保存当前工作台数据。尚未创建或购买任何托管服务。

## 同步行为及限制

打开、获得焦点、从后台切回、恢复联网时读取服务器；不再每3秒轮询。操作保存后重新读取。日程写入使用版本号及操作ID，旧版本不能覆盖新版本。保持打开且始终在前台的另一设备不会自动刷新，切回即可更新。

网络失败时显示失败，表单不因失败关闭。当前不支持离线自动排队提交；关闭页面前应恢复联网并重新保存。聊天草稿和部分学习字段还不支持逐字段多设备合并，避免同时编辑同一字段。

云端密码登录使用 Secure/HttpOnly Cookie，30天有效；API读取也要求登录，且没有本机地址绕过。模型凭证使用 AES-256-GCM，由环境密钥加密。服务重启后客户端刷新会话令牌。
